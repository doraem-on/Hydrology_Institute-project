# Direct warning forecasts at Khadda

Reproduce from the project root with the established Python environment and the [archived GFS inputs](../gandak_warning/README.md).

    PYTHONPATH=src .venv/bin/python scripts/khadda_multiseason.py

**Gauge sources.** source_stage.csv.gz preserves the June–October HHS water levels (metres) for Khadda (009-MGD4PTN) and upstream Triveni (008-MGD4PTN) from the [CWC historical archive](https://diagram-chasing.github.io/cwc-flood-forecasts/hourly.parquet) (ODbL). Archive SHA-256 is 57b71f7cba501e2218278f458c61f8002f21d971dd644d60bc5a0a47838e6e66. To rebuild the extract, select these station codes, datatype HHS, unit m and months 6–10, then pivot value on timestamp and station. Timestamps are local IST. The first season starts August 3, 2023, and the last ends October 27, 2026. No interpolation, revision vintages or delivery logs are available.

**Experiment.** Fit one direct ridge regression (penalty 1) per lead 1–24 h and predict change from the latest local reading. Each input gauge contributes level and 1, 3, 6, 12 and 24 h differences, requiring 25 consecutive readings. Assume a one-hour delivery lag. Require both gauges on training and evaluation rows for a paired comparison. For each test year, use all available earlier seasons with target timestamp strictly before June 1 of the test year. The 2023 observations initialize training. Simulated input failures repeat every seventh day from June 1, from 00:00 to 05:59. The outage run falls back to the local prediction until a complete clean history returns. The stuck-sensor run silently repeats the last reading during that block. Both use the original trained coefficients. These are deliberate stress tests and carry no attribution of fault.

**Events.** An onset reaches or exceeds 95 m (warning) or 96 m (danger) after 24 consecutive observations strictly below that level. These are gauge crossings and can recur in the same hydrological episode. An advance alert at an eligible below-level hour requires any predicted stage in the next 24 hours at or above the threshold. Matched hours require all model predictions and all future observations. False alert hours have no observed crossing in that window. A run is a contiguous sequence of false hours. paired_leads.csv retains misses as blanks. The median gain is computed only where both rules warned. The full event counts also include events caught by just one rule. The counts at 95 m and 96 m can describe the same flood.

**Weather.** The smaller weather experiment starts with the archived 2026 GFS window (July 30) and freezes parameters before September 16. The same complete training and issue rows are used for local, upstream and upstream plus rain. Rain uses the existing upstream three-point GFS mean, 00 UTC cycles aged at least 12 hours, six previous hourly endpoints and forecast accumulation to the target. Scores for this experiment should not be pooled with the cross-season scores.

**Official products.** official_bulletins.csv transcribes all ten date-prefixed FMIS daily water level and flood forecast sheets in the [Bihar WRD bulletin directory](https://www.fmiscwrdbihar.gov.in/bulletin/) when checked on November 10, 2026. Each row links the source PDF and includes its SHA-256. Its masthead gives a 15:00 IST issue time. The Khadda row contains the observed 08:00 level followed by three 15:00 forecasts. We matched the second forecast to the following day's 15:00 observation and to the study models issued exactly 24 h earlier. Scores count high values at that one hour, not an alert for any hour in a whole day. The bulletin dates are sparse and mostly quiet. Archival copies cannot identify the first warning received in a village. For a longer-horizon advisory, the [July 3, 2024 CWC report](https://cwc.gov.in/sites/default/files/dfsitrepca-03.07.2024.pdf) lists severe conditions at Khadda for July 6. Its issue date is known, but a precise issue hour is not documented here.
